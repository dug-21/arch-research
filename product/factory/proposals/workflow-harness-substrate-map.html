Workflow-harness · the substrate

Where Unimatrix fits, what Jurati is, and how work is bounded

Definitions flow down from the owner under forge custody. The queen turns them into a bounded unit of work and calls the model once per step across a single edge. The model can ask for effects but cannot cause them — every effect leaves through one of four planes holding credentials the model does not. Each plane must prove it refuses before the run starts.

The three answers

What was blocking the decision

Two questions have been unanswerable, and a third has been open since the theme was seeded.

Where does Unimatrix fit?
Two places, never a third.

The knowledge layer, and one of four enforcement planes — the semantic-commitment leg. Never the workflow-definition store, never the event sink: both would make it the orchestrator issue #12 forbids, and both fight its read/write/version profile. Three profiles, three stores.

The sharp part: Unimatrix is today an enforcement plane that does not enforce. Its custody is real; its input is authored by the governed party.

Is Jurati one capability or several?
One object, six capabilities — four of them ours.

Not five independent gaps but one missing object model with five faces. The seams are cut by custody and rate-of-change, not by feature — which is what makes the list terminate rather than grow.

The decomposition has literally never been done: the theme namespace holds 22 technology nodes and zero capability nodes, re-checked live.

Graph engine, or separate substrate?
Resolved — by rejecting the fork.

Git files are the source of truth; the forge holds custody; any store is a derived, rebuildable index with no authority. The custody predicate refuses both branches identically, so the fork was asked one altitude below where the decision lives.

Falsifier: rebuild the index from the pinned ref and diff it. If it differs in any field the queen reads, the store held authority it should not have.

The map

Ten boundaries, four exits

A box is a boundary of responsibility — not a service, process, repository or deployable. Two boxes may live in one file. The map is silent on deployment on purpose.

How work is bounded

One invariant, twelve hops

The trace below is a real unit of work from this month, not a toy: read seven findings files, write one synthesis report, write four knowledge nodes, commit path-scoped.

The invariant

Work enters as a definition under external custody, crosses the dispatch edge exactly once per step, and leaves through exactly four effect planes. There is no fifth exit. Nothing the model says is ever consumed as fact about what happened — only what a plane recorded is.

The first half of that invariant is a design intention. The second half is mechanically checkable. The sole-path claim — there is no fifth exit — is not demonstrated for any plane in this repository today, and every authority claim on the map rests on it. That is the single most expensive unknown on this page.

Where the live failure is — hops 10 and 11, in our own garage, right now

The curator is the single writer. The rule that stops it claiming proof without an artifact is prose in a role file. The evidence field is authored by the same agent the rule governs, and the actor identity is a self-asserted string.

That is the custody predicate firing inside our own toolchain, on the control the whole methodology is named after. The MetaHarness run found seven instances of this shape in someone else's repository. This is the eighth, and it is ours.

The minimum defensible set is what survives

Controls 1, 2, 3, 5, 9 and 10 — four externally-custodied planes, one derivation whose input the governed party cannot author, and one prober. Four of the ten are refused at admission; two of those four are ours and fixable, one is unfixable and must be relabelled, one must be renamed. The map has two in-process controls and names both as failing — it does not reproduce the seven-gates-zero-boundaries shape it was drawn against.

Stated plainly

Controls 1, 5, 6, 8, 9 and 10 have no implementation in this repository at all. Controls 2 and 3 exist as configuration whose effective value has never been measured. Zero of the ten have ever produced a recorded refusal we generated ourselves.

Build markers

Four boxes, and what forced each

A Build means no plausible adopt or assemble route was found, or a custody requirement nothing available satisfies. Four is more than anyone would like.

Bound derivation Build

Every component on the shelf assumes the principal is a program with a statically declared interface — a build target, a WIT world, a layout, a schema, frontmatter. An LLM agent has none. The assumption is invisible because it is universal. This is the only box on the map that is differentiated rather than merely necessary.

Unit-of-work object Build

Not a missing feature — a missing noun. Every available switch is a predicate over the wrong one: tool calls, pipelines, sessions, files, branches. 43 of 128 canonical abilities are faces of it. Caveat: 11 of the 128 have their absence contested by an unflipped switch. Flip those first.

Plane liveness prober Build

Nothing in this theme detects a control that is present, configured, believed and inert. No product ships a seeded-refusal preflight. It is also the cheapest box on the map and the only one runnable against our existing setup at zero external cost.

Write-time gate events Build

Refusals and owner silence are not presently artifacts and cannot be reconstructed. Their absence biases trust-graduation counts in the agent's favour — the record quietly flatters the thing it is meant to check.

If you build one thing

Build the prober. It is small, it attacks the failure mode this theme has now documented three times independently, it runs against the garage as it stands, and it would be this theme's first demonstrated-by-us artifact. The theme currently has zero.

The counter-case

The strongest objection, unanswered

The map treats the queen as a single trust boundary while arguing that in-process controls fail the custody predicate. But from your adversary model the queen is also a governed party — it can be prompt-injected, mis-configured, or simply wrong.

Under that reading, controls 4 and 8 fail, control 9's observer collapses into the observed if the queen takes its own observations, and the four external planes become the only real controls on the page. If that reading holds, the honest smallest defensible substrate is four adopted planes plus a prober, and no Jurati at all until definition integrity is externally custodied.

What can be answered: the queen buys sequencing determinism and the join key. Neither is an authority claim, and neither should ever be described as one.

What cannot: whether a queen that is itself unattested can carry the observation without the observer collapsing into the observed. The fix — take the observation at the plane — is stated in the register, but no plane we have adopted emits a demand set in a form the derivation can consume. That is a genuine hole in the differentiating leg, found by writing this document, and it is recorded nowhere in the graph.
