## Determining result

**[Static code evidence]** MetaHarness does contain small code seams, but “MetaHarness” is not itself a coherent reuse boundary. The useful code units are source-level functions or narrowly selected modules inside the generator, router, and JS kernel; the published generator-library alias expands to the full `metaharness` runtime fan-out, most published entrypoints require unbuilt `dist/**`, and the kernel package expands into required RuVector, optional native, generated WASM, peer, state, and environment-selected behavior. [C1][C2][C3]

**[Static code evidence]** The repository's upgrade story is not closed at this cutoff. Its manifest records rendered-file hashes and generation variables, and `harness upgrade` is exposed through the subcommand dispatcher, but `template_version` is always `0.0.0`; the command re-renders only the bundled base template rather than replaying scaffold host/feature overlays; `applyPlan()` neither removes `removed` files nor rewrites the manifest; added-file parent directories are not created; conflict application destroys the clean pre-upgrade local representation by replacing it with markers or creates an untracked `.rej`; and no stored old content exists for an actual three-way merge. The exposed mechanism is an incomplete upgrade lifecycle. [C4][C5]

**[Static code evidence] A correct isolation concept shipped with an unsafe default — the load-bearing finding of this rework.** `packages/projects/src/sandbox.ts` (131 lines, MIT, imports only `node:child_process`) wraps an arbitrary command in `unshare -rn` — a new Linux user + network namespace with no configured interfaces — precisely because, in its own words, "the discovery/verifier pipeline runs GENERATED and THIRD-PARTY code (proofs, candidate exploits, untrusted snippets)." Its availability check is the best idea in the module and one of the better clean-room concepts in the repository: `sandboxAvailable()` executes `unshare -rn true`, testing whether the isolation **operation** actually succeeds under the exact flags the wrapper will use, rather than whether the binary exists. **But `buildSandboxArgv()` fails open.** When the probe returns false it returns `{ cmd: bin, argv: args }` — the bare command — and the code runs with no isolation at all. `SandboxResult` carries no field distinguishing an isolated run from an unisolated one, so no caller can detect the degraded mode, and the probe is evaluated exactly once at module load (`const CACHED_AVAILABLE: boolean = sandboxAvailable()`). `runSandboxed()` has **no caller anywhere in the pinned repository** (`git grep`: only the `export *` re-export in `index.ts` and the module's own tests — which bounds the claim rather than proving the function dead, since an out-of-repo consumer of `@metaharness/projects` could import it), while **ten sites in the same package execute model-generated Python directly** through `execFileSync('python3', ['-I','-B', …])` — `bin/darwin-discover.mjs:130` and nine `bench/*.bench.mjs` — never through the sandbox. The bypass is **designed into the shared specification, not incidental**: `src/verifiers.ts` performs no execution at all (its own header: "This module performs NO process execution") and instead *defines* the vector every consumer uses — `PYTHON = { bin: 'python3', args: (file, argsJson) => ['-I','-B', file, argsJson] }` at L102–105 — a bare interpreter invocation that never routes through `buildSandboxArgv()`. And the bypass is **partial, which is the precise part**: the direct sites do replicate the env-hygiene half (`-I` plus `env: { PATH, PYTHONDONTWRITEBYTECODE }`, so no API key reaches the child) but not the namespace half — so untrusted generated code runs with **full network access**, which is exactly and only the threat `sandbox.ts`'s own header names. For a substrate meant to run untrusted generated code this is not a caveat to be filed under drift: **a gate that reads as protection while providing none is a worse artifact than no gate**, because it removes the pressure to build a real one and it makes the unisolated path indistinguishable from the isolated one in every log and result. The concept is adoptable; that default is the thing to invert. [C19]

**[Static code evidence]** The ARC Python bridge (`packages/arc-agi-3/src/python-bridge.ts`, 983 lines + `packages/arc-agi-3/python/bridge.py`, 868 lines) is the repository's only cross-language subprocess seam, and its protocol discipline is the **opposite** default: every protocol violation transitions to a terminal `failed` state, and the Python side refuses to start (`SystemExit(2)`) when the installed SDK versions do not equal its expected pins. As code it is the largest closure in this workstream — an interpreter, two unlocked PyPI pins, a network endpoint and a live credential — and as a protocol it is portable at low cost. [C20][C21]

**[Unverified/inference]** Portfolio A below is deliberately small and conditional. Portfolio B is broader because the durable value lies in mechanisms—generation envelopes, projection custody, explicit late binding, upgrade transactions, conformance across fallback implementations, and one-way import ledgers—whose invariants can be preserved without copying MetaHarness's coupled implementation. No row recommends adoption or designs Jurati.

## Upgrade mechanics at cutoff

```text
current project manifest (vars + old content hashes)
             + caller-supplied latest rendered hashes/content
             -> planUpgrade: added / removed / changed(clean|conflict)
             -> applyPlan: write added + changed only
                            ├─ clean: overwrite
                            └─ conflict: replace with markers OR add .rej

missing from the transaction:
  resolve/pin old and new template versions; retain old content; create added parents;
  replay host/feature/post-generation producers;
  delete removed files; update manifest + self-hash; include post-generation overlays;
  preserve rollback state; verify completed output
```

- **[Source claim]** comments describe a Copier-style regenerate–diff–merge and call `.harness/manifest.json` the load-bearing upgrade/eject source of truth. [C4][C5]
- **[Static code evidence]** `harness upgrade` is routed through `subcommands.ts` to `upgradeCmd()`. The command resolves the current package's bundled `templateDir(manifest.template)` and walks that base directory with saved vars; it does not call the original scaffold composition that added host files, multi-host dependencies, sessions, MCP, WASM, or other overlays. Those prior generated files can consequently appear `removed` from the upstream map, while `applyPlan()` ignores removals. [C4]
- **[Static code evidence]** `planUpgrade()` can detect local modification only for paths whose upstream hash changed. A locally modified file whose template hash did not change is absent from the plan; a locally deleted changed file is classified `clean`. That is sufficient for a selective update decision, not a full workspace drift report. [C4]
- **[Static code evidence]** the manifest carries generator, template, vars, hosts, rendered hashes, timestamp, optional surface/kernel version, and a schema literal `1`; it does not carry a resolvable template source/ref, dependency lock/digest, old contents, host-schema versions, or post-generation producer ledger. `template_version` is hard-coded `0.0.0`. [C5]
- **[Static code evidence]** the sibling manifest SHA-256 is written by scaffolding but not read by `planUpgrade()`; `--with-wasm` mutates output after initial fingerprinting; browser output uses an incompatible, unhashed manifest; session code and host projections are duplicated; example host wrappers resolve `@latest`. These form independent drift domains with no common invalidation event. [C13][C15]
- **[Static code evidence]** repository automation includes CI/publish/published-smoke workflows, Dependabot, and a narrow scheduled `META_PROXY_VERSION` release comparison. The proxy checker treats inability to read the latest release as “skipping (not a drift).” No equivalent static workflow was found that proves CLI/browser projection parity, generated catalog freshness, template package/version provenance, native/WASM/JS semantic equivalence, or `@latest` consumer reproducibility. Presence of tests/workflows is not demonstrated success. [C16]

## Portfolio B — portable CONCEPTS for clean-room reimplementation

These are mechanisms or governance/evaluation methods, not imported code. Each item names the invariant worth preserving without copying implementation.

1. **[Unverified/inference] Immutable generation envelope.** Preserve: one finalized record binds producer identity/version/source digest, template identity/version/source digest, normalized inputs, host-schema versions, dependency resolution, every output byte and mode, every post-generator overlay, and witness/attestation. Finalize only after all producers finish. MetaHarness's pre-overlay hashes and split manifest hash are the negative case. [C5][C15]
2. **[Unverified/inference] Transactional upgrade with explicit three-way custody.** Preserve: immutable base content (or resolvable base digest), immutable candidate content, current local content, complete add/change/remove decisions, preview, rollback, conflict artifacts that do not destroy local state, atomic commit, and envelope refresh only after verification. Hash-only history cannot produce a genuine merge. [C4]
3. **[Unverified/inference] Stable definition → shared intermediate representation → deterministic projections.** Preserve: a single typed IR feeds CLI, browser, host configs, manifests, docs, and runtime registrations; structural equivalence is checked across projections. Do not preserve duplicated emitter files or comments requiring lockstep. [C13][C15]
4. **[Unverified/inference] Authored/generated custody and invalidation graph.** Preserve: every generated or copied artifact names its authoritative producer/input and invalidation trigger; hand-authored exceptions are explicit; generated output is never silently authoritative. [C15]
5. **[Unverified/inference] Explicit late-binding resolver policy.** Preserve: every registry tag, optional backend, environment-selected module, external executable, network endpoint, and host schema is a declared resolver with provenance, allowed range, cache/replay behavior, observability, and fail-open/fail-closed semantics. Avoid burying `@latest` or ambient CWD paths in emitted strings. [C3][C13]
6. **[Unverified/inference] Multi-backend conformance, not fallback optimism.** Preserve: one versioned behavioral contract and fixtures run independently against canonical, native, WASM, and fallback implementations; backend choice and fallback are evidence-visible. MetaHarness's interface and fail-loud forced selection are useful concepts; comments saying rules mirror exactly are not drift control. [C8]
7. **[Unverified/inference] Versioned copied-code protocol.** Preserve: if generated projects receive source copies, embed protocol/schema version, upstream digest, conformance fixtures, and a migration path. Otherwise import an owned library. The invariant is behavioral compatibility across forks, not byte-for-byte comments. [C9]
8. **[Unverified/inference] One-way importer with loss/provenance ledger.** Preserve: pin and hash the source format, parse structured data, enumerate retained/translated/rejected state before mutation, retain attribution, and stamp the result with the importer version. Do not preserve broad textual replacement or ruflo-specific names. [C12]
9. **[Unverified/inference] Projection is not authority.** Preserve: host configuration generation remains separate from enforcement and credential custody. A generated allow/deny file or transport skeleton is a projection until an independently controlled decision point protects an operation. This carries forward the wfh-007 gate-input-independence invariant without treating MetaHarness code as its implementation. [C17]
10. **[Unverified/inference] Dependency events invalidate evidence.** Preserve: version, lock, generated artifact, host schema, backend, or policy-input changes create explicit revalidation events scoped to the affected claim. Multiple locks and unlocked/generated roots must not share one undifferentiated “tested version.” [C3][C17]
11. **[Unverified/inference] Producer→artifact→consumer coverage ledger.** Preserve: architecture completeness is checked by typed edges including generation, dynamic loading, filesystem/process/network prerequisites, and deployment consumers—not manifests alone. Orphans and unresolved dynamic edges remain visible gaps. [C15]
12. **[Unverified/inference] Drift checker failures are findings, not passes.** Preserve: an unavailable registry/API/input produces `unknown` or blocks freshness claims; it cannot be normalized to “not drift.” This is a governance invariant illustrated by the proxy workflow's skip branch. [C16]
13. **[Unverified/inference] Probe the real operation, not the binary's presence.** Preserve: a capability gate establishes its capability by *performing* the exact protected operation under the exact flags it will later use — `unshare -rn true`, a no-op inside a real user+network namespace — not by finding an executable on `PATH` or reading a `--version` string. **[Source claim, comment]** the module names the failure mode this defeats, and it is the right one: in containerized CI the `unshare` binary is present and `--version` succeeds while unprivileged user namespaces are restricted, so `-rn` fails with `EPERM` only at the moment isolation was supposed to apply. Generalize it to every capability a Jurati substrate asserts — sandbox, signer, egress block, filesystem restriction, credential separation: **the probe is a rehearsal, not an inventory**, and an inventory-shaped check is a false positive machine. Preserve also the layering that makes it testable: a pure argv-computing function with an injectable capability flag, so the wrapping logic is unit-testable with no spawning. Do **not** preserve what the probe result is then used for (item 15). [C19]
14. **[Unverified/inference] Fail-closed subprocess protocol with an explicit environment allowlist.** Preserve, from the ARC bridge: one in-flight request at a time over JSON-lines on stdio; id-matched `{id, ok, result|error}` envelopes; bounded request and response line sizes; a single typed client-visible error shape; and an unconditional transition to a terminal `failed` state on **every** protocol violation — unsolicited response, malformed JSON, malformed envelope, oversize line, empty line, unexpected stdout close, write failure, timeout. Degradation is never a fallback path; there is no branch that continues with a weaker guarantee. Preserve the child environment as an **explicit allowlist** rather than an inherited environment with subtractions; stdout reserved as a protocol-only channel with library logging redirected to stderr *during import*; stderr drained but never mirrored into error text where it could carry credentials; secret redaction applied to log records and truncated error messages; independent validation of the same endpoint allowlist on both sides of the boundary; and startup refusal (`exit 2`) when installed dependency versions do not equal the expected pins. Do **not** preserve: the allowlist is overridable by caller-supplied `env` spread after it, and the pin is duplicated between manifest and code. [C20][C21]

15. **[Unverified/inference] A gate's input must be observed, never declared by the governed party.** Preserve the *rail* idea — a small set of named, independently evaluable refusals screening a proposed mutation before it is benchmarked. Reject the input path: `no-bypass-sandbox` decides on `CandidateChange.bypassesSandbox`, a boolean the proposer sets. Jurati's equivalent must derive each rail's input from something the proposer cannot author — the diff itself, a static analysis of it, or the observed syscall/exec surface of the run — which is the wfh-007 gate-input-independence invariant applied to a self-improvement loop rather than to a reviewer. Our own `agent_id` rule is the same lesson in the same shape. [C19][C17]

### Counter-lesson — a correct concept with an unsafe default is a worse artifact than no gate

**[Static code evidence]** `sandbox.ts` gets concept 13 right and then spends it. `buildSandboxArgv()` reads:

```ts
if (available) {
  return { cmd: 'unshare', argv: ['-rn', bin, ...args] };
}
return { cmd: bin, argv: args };
```

When the probe fails, the caller receives the **bare command** and runs it with no isolation. Three properties compound:

1. **[SCE] No signal.** `SandboxResult` is `{ stdout, ok, error? }`. Nothing in the return value, and nothing in the logs, distinguishes a run inside a network namespace from a run outside one. The one thing a degraded mode must do — say so — is not done. This is the same invariant wfh-007 records as *degraded or missing evidence must fail closed at consequence altitude*, and the same one W7 already finds contradicted by the witness path; the sandbox is a second instance. [C17]
2. **[SCE] Cached once.** `const CACHED_AVAILABLE: boolean = sandboxAvailable()` is evaluated at module import. A single probe at process start decides the isolation posture of every later execution.
3. **[SCE] The gate is unwired while the protected operation runs beside it — and the bypass is specified, not accidental.** `runSandboxed()` has no caller in the pinned tree outside its own tests (bounded, not proven dead: `index.ts` re-exports it with `export *`, so an out-of-repo consumer could import it). The operations it exists to protect — executing model-generated Python — run at **ten** sites in the same package via `execFileSync('python3', ['-I','-B', …])`: `bin/darwin-discover.mjs:130` and nine `bench/*.bench.mjs`. The shared registry those sites follow, `src/verifiers.ts`, executes nothing itself and *defines* the vector as `bin: 'python3'`, `args: ['-I','-B', file, argsJson]` (L102–105) — the unsandboxed invocation is the specified one. **[Source claim]** `verifiers.ts`'s header says "a proof is run against the target in an isolated subprocess"; `darwin-discover.mjs`'s header says "an ISOLATED `python3 -I -B` execution verifier". **[SCE]** `-I` is Python *interpreter* isolation — ignore environment variables and user site-packages — and confers no process, network, or filesystem isolation. **[SCE] The bypass is partial and the missing half is the whole point:** those sites do carry the env-hygiene half (`-I` plus `env: { PATH, PYTHONDONTWRITEBYTECODE }`, so no credential reaches the child) and omit only the namespace half, leaving untrusted generated code with **full network access** — the single threat `sandbox.ts`'s header was written to defeat ("a malicious or buggy proof could exfiltrate data, fetch a second-stage payload, or phone home"). **[Unverified/inference]** the word "isolated" is doing load-bearing work in two documentation headers that the code does not do at those call sites.
4. **[SCE] The rail that names this failure cannot detect it.** `safety-rails.ts` ships a `no-bypass-sandbox` rail (L97–98) that rejects a mutation when `c.bypassesSandbox` is true. `bypassesSandbox` is a field of `CandidateChange` (L33) — the proposed mutation — i.e. **a boolean supplied by the proposer, the party the rail governs.** **[Unverified/inference]** a guard whose only input is self-declared by the governed party is defeated by declaring `false`; it is a label, not a control. This rhymes exactly with the garage's own corrected `agent_id` rule — persisted self-assertion is reliable for reconstructing what happened and useless for establishing who is accountable, and one must never build an authority check on a field the guarded party writes. Preserving the *rail vocabulary* without an independently observed input reproduces the same false assurance one level up.

**[Unverified/inference] The lesson, stated as sharply as the concept:** for a substrate that runs untrusted generated code, a fail-open isolation gate is *net negative*. It is worse than no gate, because no gate is honestly frightening and prompts a real containment decision, whereas this one appears in the tree, in the exports, in the safety-rail vocabulary (`no-bypass-sandbox`), and in a test file with a network-exfiltration assertion — while the assertion `skipIf`s out on precisely the hosts where the isolation silently does not apply, and the production path never calls it at all. Reviewers reasonably read that surface as containment.

**[Unverified/inference] The inversion, which is cheap:** when the probe fails, refuse — return an error or a value the spawner cannot execute, rather than the bare command; make the isolation fact part of the result (`isolated: boolean`) so a caller can neither ignore it nor mistake it; re-probe per run, or treat the cached negative as a startup failure rather than a per-call default; and route the protected operation through the gate rather than beside it. Nothing here is demonstrated-by-us: this is what the source says, not an observed execution. A later validated scope would have to exercise the unavailable-probe path on a host where `unshare -rn` fails.
