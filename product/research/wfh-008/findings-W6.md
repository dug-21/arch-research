# wfh-008 W6 — Security and authority boundary

**Role:** `factory-researcher` · **workstream:** W6 only · **method:** static inspection only  
**Cutoff:** `ruvnet/metaharness` commit `6f8c60216f47eac391a076fe27fd804470a07e10`; `ruvnet/ruflo` commit `d33ef4bf8ab27a8f9ef08352c9c293b53312a861`; retrieved 2026-08-28.  
**Evidence labels:** **source claim** = documentation/comment/ADR; **static code evidence** = traced source/config path, not execution; **prior demonstrated evidence** = artifact from an earlier garage run; **unverified/inference** = conclusion not established dynamically. Nothing here is demonstrated-by-us evidence.

## Headline

**Static code evidence:** MetaHarness contains useful deterministic authorization *mechanisms*, but does not present one closed authority boundary. Its main `PolicyGate` is optional and defaults to absent at kernel construction; when present it evaluates before the selected worker runs, but the caller constructing the kernel supplies the rules, risk ceiling, action mapping, agents, and policy object in the same process. Host adapters mostly generate settings that a project/runtime owner can edit. The stronger CASA story deliberately splits compilation in MetaHarness from enforcement in ruflo; at this cutoff the ruflo Rust gate exists as a pure function, but repository-wide production call-site tracing did not establish that it mediates every dispatch. Therefore the directly reusable code is mostly checker/serialization machinery; the valuable portable concept is **compiler/controller separation plus external custody of the enforcing credential/path**.

**Static code evidence — sharpening added after the round-2 coverage re-audit:** two further gate classes were missed by W6's first pass and are now recorded. Both instantiate the same pattern rather than qualifying it, and one instantiates it more severely than anything else in this file. The ARC Python bridge's egress allowlist, operation mode and `ARC_API_KEY` custody are all supplied by the governed embedding process — a self-imposed restriction. The `packages/projects` sandbox is worse than same-authority: it is a stated isolation gate for **generated and third-party code** that (i) **fails open**, returning the bare unisolated command when its `unshare -rn` probe fails, (ii) has **no in-repo caller**, and (iii) is bypassed by the sites that actually execute model-generated Python. An isolation gate with no caller, that fails open when its probe fails, and whose real execution sites route around it, **does not mediate anything** — the sole-path question is not merely unproven here, it is answered negatively by static structure. This does not soften the headline; it supplies its clearest instance. The gates found in MetaHarness are honest *mechanisms* that the same authority may omit, widen, or walk past.

**Unverified/inference:** No MetaHarness mechanism inspected here meets Jurati's admission test by source structure alone: seed a violation and require a refusal from a plane whose credential/configuration the governed actor cannot alter. A later validated scope must prove that custody property against a real host and process topology.

### B. Portable concepts for clean-room replication

1. **Compile intent/config into a bounded, serializable authority envelope; enforce it in a different runtime.** Valuable shape, but Jurati must own the scope vocabulary and enforce from a credential/path unavailable to the compiler or worker.
2. **Deny precedence + explicit allow + malformed-input denial.** The simple decision algebra is portable and auditable. Carry expiry, budget, network, destructive, namespace, and consequence fields through one typed contract; do not silently delegate some fields to unnamed subsystems.
3. **Pre-operation decision plus post-operation receipt.** Keep authorization and evidence separate: a signed receipt cannot retroactively authorize an effect.
4. **Degraded-mode truthfulness.** Returning `{unverified:true}` rather than treating shape validity as crypto validity is a good pattern. Jurati's consequential path should make degraded mode incapable, not merely require an override flag.
5. **Host capability compilation.** Translate a host-neutral declaration into the host's actual authority mechanism, but require a loss report. MetaHarness shows why: “deny,” “ask,” a reduced GitHub token, and a warning file are not equivalent outputs.
6. **Honest unsupported-host adapter.** Emitting `SANDBOX-REQUIRED.md` instead of claiming Prime Agent enforcement is a governance pattern worth preserving, though a document must never be counted as a gate.
7. **Monotone delegated envelopes.** ruflo's `isEnvelopeReduction`/depth decrement is a portable checker concept. It becomes security only when every delegation and invocation is forced through it and the child cannot replace the parent envelope.
8. **Probe the real operation, not the binary's presence — then fail closed on the probe, not open.** `sandboxAvailable()` runs `unshare -rn true`, the exact operation the gate depends on, rather than checking that an `unshare` binary exists, precisely because a container can have the binary while unprivileged user namespaces are denied (module comment L27–34). That is the strongest capability-detection idea in the repository and the single most portable concept W6 found for Jurati: a capability check must exercise the capability. **Carry it with its counter-lesson attached, because MetaHarness gets the second half wrong three ways at once.** (a) *Default:* the probe's negative answer is routed to `return { cmd: bin, argv: args }` (L74) — no isolation, no signal, execution proceeds. A capability probe's value is telling you the capability is absent; spending that answer on silent degradation discards it. Jurati's rule: a probe that answers "cannot isolate" must make the protected operation **incapable**, not unprotected. (b) *Sole path:* `runSandboxed()` has no caller and the real execution sites go around it. A gate is only a gate if the protected operation cannot be reached except through it — enumerate the execution sites and prove the set is closed, because the enumeration, not the wrapper, is the security property. (c) *Staleness:* one probe cached at module import (L46) makes the gate's view of the world permanently as old as the process. Re-evaluate, or bind the answer to the operation.
9. **Fail-closed, serial, bounded subprocess protocol with an explicit inherited-env allowlist.** `PythonArcBridge` is a good shape independent of its content: a long-lived JSON-lines child, one in-flight request at a time, hard line-byte and timeout ceilings, malformed-envelope ⇒ `#failClosed`, stderr drained but never surfaced into error text (L541–543), secret redaction inside the child (`bridge.py` L155–161), version pins asserted on *both* sides of the boundary with a hard exit on mismatch (`bridge.py` L26–43), and — the portable core — an **enumerated allowlist of environment keys the child may inherit** rather than a denylist of keys to strip. Counter-lesson: the allowlist is undone by its own composition. `options.env` is merged *after* the allowlist with no filtering (L514–518), so any caller reintroduces exactly what the allowlist excluded; the repository's own tests inject `PYTHONPATH` that way. If Jurati adopts an inherited-env allowlist, the merge order must not be caller-last, and the same applies to the host allowlist, which here validates hostname *shape* and not membership.

## Explicit static-assurance limits and residue sweeps

- **Sweep record — corrected, and the correction is the point.** Two residue sweeps were originally run: (1) authority terms over MetaHarness source/config/docs, then narrowed to executable packages/crates; (2) call-site searches for `PolicyGate`, claims dispatch, witness verification, CASA, ruflo policy engine, and authorization propagation. Those sweeps concluded that no additional W6-owned gate class existed. **That conclusion was wrong and is withdrawn.** The round-2 coverage re-audit found two unowned gate classes — the ARC bridge egress/credential path and the `packages/projects` isolation gate — now added to both tables above. The defect was in the sweeps' alphabet, not their rigour: sweep 2 searched the *vocabulary of the gates already known* (`PolicyGate`, CASA, witness, claims, propagator) rather than the *vocabulary of protected operations* (process spawn, interpreter invocation, network egress, credential forwarding). A gate named nothing like the gates you have found is invisible to a name-driven sweep. The corrected sweep is operation-driven: enumerate every `execFileSync`/`spawnSync`/`spawn` literal and every credential-bearing environment key across shipped source and bins, then ask what decides for each. Run that way it yields the two rows above plus the already-owned classes. **[Static code evidence]**
- **Consequence for predicate 4:** W6 no longer asserts that its gate enumeration is closed. It asserts that it is closed *against an operation-driven sweep at this cutoff*, which is a weaker and honest claim. A gate class reachable only through a dynamic import, a generated harness, or an out-of-repo consumer would still be missed.
- **Unverified:** generated host configuration was not loaded into any host; settings precedence, escape flags, admin roles, token contents, Environment protection, and sandbox behavior were not tested.
- **Unverified:** no generator, test, build, model, network service, package installation, or exploit was run. Checked-in tests establish authored intent only.
- **Unverified:** no deployed identity provider, key broker, revocation system, protected signing service, or externally held approval issuer was established for MetaHarness.
- **Unverified — the two new rows, explicitly.** `unshare -rn` was not run; `sandboxAvailable()` was not evaluated; no verifier, bench, or `darwin-discover` invocation was executed; no ARC request was issued and no credential was exercised; no refusal was seed-and-observed. **The fail-open branch is read from source, not witnessed.** Static structure establishes that `buildSandboxArgv()` returns the unwrapped command on a false probe and that the direct `execFileSync('python3', …)` sites exist and appear reachable — it cannot establish that either path executes, that the probe ever returns false on any real host, or that an operator ever reaches the bypassing path.
- **Unverified:** `runSandboxed()`'s absence of an in-repo caller is static-grep evidence at this cutoff and does not prove the function is dead — `src/index.ts` re-exports it, so an out-of-repo consumer of `@metaharness/projects` could import it. That possibility does not repair the fail-open default or the in-repo bypass; it only bounds the dead-code claim. Note also that `packages/projects/dist/**` is not tracked, so the shipped artifact was not inspected — only its source.
- **Naming collision, recorded to prevent a false match:** `packages/darwin-mode/src/sandbox.ts` is an unrelated module (variant-task execution) with no `unshare` and no isolation role. Only `packages/projects/src/sandbox.ts` is the gate described above.
- **Unresolved static gap:** MetaHarness CASA comments cite ruflo paths such as `plugins/ruflo-agntcy/src/casa/enforce.ts`, while the inspected ruflo checkout implements the Rust gate at `v3/crates/ruflo-agntcy/src/envelope.rs`. That documentation/path drift is material because the supposed runtime boundary is cross-repository and copied by convention.
- **Determining follow-on evidence:** pin both repositories; generate one narrowly scoped harness; place the enforcer and clock/key/config under a separate OS/service identity; attempt direct host invocation, policy omission/mutation, translator widening, expired/malformed envelopes, wildcard claims, unsigned/missing witness, and admin/config bypass; require externally recorded refusals and verify upgrade/schema drift replay.
