# L2 — Constraint inversion

**Run:** `wfh-004` · Issue #48 · phase `hypothesize` · lens L2 · read-only, zero graph writes.
**Sources:** `surface/BRIEFING.md`, `surface/W0-a|b|c|d`, `SCOPE.md` §3.2/§3.3/§4.

**Method note.** Every candidate below was produced by taking an inherited constraint, a §3.2 layering edge, or an unexamined assumption, and asking what its negation makes expressible. The verdict table (§2) is the analytical core; the register (§1) is what fell out of the inversions that survived Rule 2. One orienting observation drives much of both: **C-1 as written forbids exactly the pattern W0-a identifies as the field's strongest shipped security** — Copilot's enforcement lives in the *storage plane* (GitHub), a plane the agent holds no admin credentials for. The inherited constraint set repeatedly encodes *who currently owns something* as *what is possible*.

## 2. The constraint verdict table (first-class deliverable)

### The four wfh-002 constraints

| Constraint | Verdict | Argument |
|---|---|---|
| **C-1** — enforcement is queen-side; a substrate cannot enforce | **SPLIT: PRACTICE for write-boundary invariants; PHYSICS for actions that never transit the substrate** | The mechanical case that the substrate *can* enforce is already in our own pain record: **P-24 — Unimatrix enforced a rate limit against us**, mid-run, deterministically. Refusing a write that violates an invariant is the same machinery as refusing the 61st tag-write in an hour. ADR-008/jurati#12 is an **ownership decision** about what the knowledge engine should be, not a statement about what a storage plane can do — and W0-a shows the field's strongest shipped security (Copilot) lives *precisely* in the storage plane. The physics half is locality: a store cannot gate an action it never sees (spawns, bash, egress). Restated for triage: *the substrate cannot orchestrate, but it can refuse* — C-1 as written conflates the two. Unlocks: L2-01, L2-02, L2-03. |
| **C-2** — semantic verdicts require LLM leaves | **PHYSICS at core; PRACTICE at its claimed scope** | Core holds mechanically: a deterministic procedure can be built for any prose predicate (a regex is one) — it will just be *wrong*; "correct semantic verdict" is not syntactically recoverable, so correctness bottoms out in inference. But the constraint's *jurisdiction* is far smaller than its current application: (a) claim **formats** can migrate to the checkable side at authoring time (L2-04); (b) most of the garage's actual failed verdicts were never semantic — role-ran, counts-match, Issue-unique, report-self-consistent are arithmetic (L2-06); (c) the calibration *around* an irreducible leaf (k-agreement) is deterministic (L2-05). C-2 is being used as a blanket excuse for checks that were always computable. |
| **C-3** — files stay source of truth | **PRACTICE** (a real economic constraint, wrongly scoped as a possibility constraint) | Two inversions. First, it is an economic argument — fighting git/editors has a cost — not a mechanical impossibility, and route-arounds pay the cost nowhere: derived indexes (L2-08) and content-pinned run snapshots (L2-07) keep files as the editable master while giving the harness what it needs. Second and sharper: **C-3 conflates two planes.** It is true of *authored intent* and already false of the *operational record* — the transcript is not user-edited and nobody minds. The plane split (L2-09) shows the constraint's actual boundary: files own what humans author; nothing forces files to own what runs emit. P-08's orphan Issue is what happens when run-state lives in an editable surface. |
| **C-4** — capability gating: an LLM cannot bind itself | **PHYSICS at core — and the core is narrower than stated; the premise is PRACTICE** | The core is the confinement problem: a principal cannot hold over itself a restriction it cannot also lift. That survives every attack constructed here, and W0-b's refinement is right: *the binding authority must be a principal the agent cannot write as.* But the stated premise — "it holds the credentials it would restrict" — is a **configuration fact, not a necessity**: a readable credential file at the same uid (W0-b §0-iii) is current practice. Brokered use-without-possession (L2-10) dissolves the premise without contradicting the core. **The generalization is the run's richest vein** — the C-4 *family*, every authority that is necessarily external: self-attestation is not attestation (L2-12); self-grading is not grading (L2-14); **a dead process cannot report its own death** — the purest physics statement on this entire surface (L2-11); self-certified completion is not completion (L2-33, and P-21 is its field evidence). Each is a binary-class differentiator per SCOPE §7 screen 6. |

### The §3.2 layering edges

| Edge | Verdict | Argument / what the inversion unlocks |
|---|---|---|
| Structure → Introspection | **SPLIT** | "Which"-introspection presupposes *an* address — analytic, true by definition. But it does not presuppose the **authored** structure: family D derives addresses from span parenting; L2-20 derives them from the emitted log; content hashes address with no author at all. "Whether"-introspection (anomaly, liveness) needs no address: P-10's death was detectable by byte-count alone. |
| Introspection → Cost management | **PRACTICE for enforcement; definitionally true for attribution** | Reservation-based enforcement (L2-16) needs no metering attribution — a lease is checked at admission, and P-15 shows the provider blocks the metering path upstream anyway. Only *"which step cost what"* is genuinely downstream, because it is which-shaped. |
| Introspection → Self-improvement | **PRACTICE as drawn** | Concurrent paired trials (L2-17) and shadow runs (L2-18) need an outcome comparator and **config identity** (L2-07 — a Structure fragment), not causal introspection. The edge is mis-anchored: self-improvement hangs off config-pinning + outcome measurement; introspection is one supplier of the measure, not a prerequisite. |
| Structure → Security enforcement | **PRACTICE** (W0-d counterexample 3, confirmed) | Action-scoped enforcement is a pattern match needing zero addressing — and it is the cheap half never configured (P-04). Role-scoped enforcement needs *principal identity* only — a fragment, not the scheme. |
| Structure → Security assurance | **SPLIT** | Auditing the single-writer rule needs verified actor identity (L2-03) — which is addressing of *actors*, not of *work*. Steps, gates, and sequence contribute nothing to it. The edge holds only if "Structure" is stretched to cover principals, which §3.1's definition does not currently do (see §4, E-4). |
| Structure → Context provisioning | **PRACTICE** | Pull-based provisioning (L2-19) needs a query policy and a ledger, not named steps. Inject-at-named-steps is one design, and the incumbent's three live injection points already run on events, not authored step names. |
