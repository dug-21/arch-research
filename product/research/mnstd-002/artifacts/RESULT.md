## Finding #357 (duplicate-anchor severity) — settled empirically

In this image, a duplicate `[[cl-clamp]]` yields **both** `STANDOC_36 "ID cl-clamp has already been used"` at
**severity 0** *and* `ISO_122 "identifier cl-clamp: duplicate"` at **severity 1**, plus an asciidoctor WARNING.
W0 and W3 each saw one of the two entries. With PDF requested (the full C1 compile) the compile also **exits 1**
(mn2pdf fatal error on the duplicate XML id), so the duplicate-anchor branch is caught by the exit code here;
W3's exit 0 was for an XML-only compile, which we did not re-run. The "exits 0 yet must FAIL" property is
demonstrated by the two other seeded branches, which the W0 rule would have passed.
