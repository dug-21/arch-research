# W2 — OpenCode v2 lifecycle, extension hooks and provider boundaries

**Evidence basis:** static source inspection of the OpenCode v2.4.1 release tag, including `@opencode/plugin` and `@opencode/core` 2.4.1 and the core package's Claude Agent SDK pin 0.3.301. The source archive fetched from GitHub codeload had SHA-256 `ee134e3c1fc1a257eae6e2dd809a81a65d2775784afbbc6faa58bfc1638a5de0`. Hosted docs describe the intended contract and may be ahead of this pin. No live provider, account, plugin, or Unimatrix behavior was exercised in W2. [Release](https://github.com/anomalyco/opencode/releases/tag/v2.4.1) · [Plugin package](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/plugin/package.json) · [Core package](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/core/package.json)

## Findings that change the platform decision

1. OpenCode has a synchronous pre-admission hook on the normal SDK and UI prompt path. Its own subagent tool calls that same path after creating an OpenCode child with `parentID`. This gives an extension a plausible child-first-request retrieval point even without a purpose-named `SubagentStart` injection hook. Look up the session by ID before injecting, classify user, child, automation and programmatic sources, and preserve the original prompt separately if it feeds learning. Prompt text mutations become the admitted conversation. Running a translation of the existing adapter alone would leave these policy and provenance questions open. [Prompt preparation](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/core/src/session/prompt.ts#L34-L90) · [Subagent create and prompt](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/core/src/tool/plugin/subagent.ts#L140-L217)
2. Both provider paths run the OpenCode session layer, but **Claude Agent is an SDK bridge to a local Claude Code process**. Its normal query sets `settingSources: []`, `settings.disableAllHooks: true`, a strict MCP config, empty native tools and skills, and an allowlist for its OpenCode tool bridge. The bridge supplies its own SDK pre/post-tool callbacks for call-ID alignment and enriched MCP output. The source therefore predicts that the user's ordinary Claude Code hook configuration will not run merely because the Claude Agent provider invokes Claude. The relevant capture strategy must be built around OpenCode's operations. Verify this with a harmless Claude-side hook sentinel and its OpenCode counterpart in the same trial. [Query options](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/core/src/plugin/provider/claude-agent/claude/query-options.ts#L85-L142) · [SDK bridge hooks](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/core/src/plugin/provider/claude-agent/tools/hooks.ts#L6-L22) · [Provider specification](https://github.com/anomalyco/opencode/blob/v2.4.1/specs/v2/claude-agent-provider.md#claude-code-settings)
3. **Pre-model context is not the same as effective provider context.** The ChatGPT request consumes the shaped OpenCode system and messages. For Claude Agent primary, compaction and generate, the built-in provider hook instead derives a Claude Code preset append via `claudeCodeInstructions` and `claudeCodeAgent`. Built-in provider hooks run before regular external plugins and the derived instructions are already computed by the time a regular external `context` hook appends a system part. The Claude message converter skips system messages. Edits to the tagged instructions part also face a second boundary because the provider prefers its structured source metadata to its rendered text. Treat an external `event.system.push()` as insufficient for Claude Agent under the pinned order. Appending to newly admitted user content is the portable candidate. A transient message transform is also a candidate, but Claude's history alignment can reconstruct, fork or replay conversation checkpoints when request history changes, so repeated context augmentation and the parked-tool continuation must be checked separately. Treat explicit writes to the provider-specific derived option as dependent on current source internals. [Provider instruction translation](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/core/src/plugin/provider/claude-agent/instructions.ts#L20-L53) · [Built-in ordering](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/core/src/plugin/internal.ts#L265-L310) · [Plugin supervisor](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/core/src/plugin/supervisor.ts#L94-L98) · [Hook execution order](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/core/src/plugin/hooks.ts#L88-L94) · [Claude request shaping](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/core/src/plugin/provider/claude-agent/language-model/claude-agent-language-model.ts#L35-L85) · [Claude message conversion](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/core/src/plugin/provider/claude-agent/language-model/convert-to-claude-message.ts#L8-L36) · [History and switching models](https://github.com/anomalyco/opencode/blob/v2.4.1/specs/v2/claude-agent-provider.md#history-and-switching-models)
4. **Capture with recovery needs two surfaces.** The experimental server-wide event stream reports live events and fails a lagging subscriber when its 4,096-item queue fills. The separate experimental per-session durable log supports exclusive `after` and continuous `follow` with a replay synchronization marker. This makes ordered recovery possible for known sessions and retained durable events. It does not supply global gap recovery or replay for ephemeral streams. A collector should discover/reconcile sessions, maintain per-session cursors and deduplication, and backfill explicitly after interruptions. The plugin event subscription is a localized live stream. Keep synchronous hook decisions small and separate from bulk capture. [Event feed](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/server/src/event-feed.ts#L8-L84) · [Per-session log route](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/protocol/src/groups/session.ts#L658-L676) · [Durable bus log](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/core/src/bus.ts#L827-L871) · [Plugin event subscription](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/core/src/plugin/host.ts#L270-L286)

## Lifecycle matrix

| Required behavior | v2.4.1 hook or data surface and timing | ChatGPT sign-in | Claude Agent |
| --- | --- | --- | --- |
| Open or resume with correct repository and lineage | `session.created` is durable and includes session, project, location, optional subpath, parent, agent and model. `session.viewed` observes a view. The core resume call wakes existing execution and does not inherently create a fresh session. Fork hook is after copying history, before returning. Use persisted identity plus execution start and admitted input to understand the meaning of resume. | OpenCode IDs and durable ledger. | Same OpenCode IDs. Separate Claude transcript UUIDs and checkpoints are managed by provider. Do not use a process startup or Claude UUID as the OpenCode session's canonical start. |
| Capture prompt before changing it | `session.hook("prompt")` sees readonly session/message IDs and mutable prompt, delivery and metadata. Activates location plugins first and runs before attachment/skill resolution and durable admission. Existing message-ID retries can reconcile before hook execution. Synthetic, shell and compaction controls have different entry paths. No provider scoping here because resolution is later. A thrown hook defect is not a typed prompt-denial contract. | Stored prompt enters native request history. Prompt admission can drive context once per admitted prompt. | Newly admitted content goes through catch-up conversion as user content. Expect separate native transcript representation and validate resume behavior. |
| Inject memory before actual request, with effective agent/model | `session.hook("context")` after model resolution, primarily mutable system/messages/tools/options. Model ref is readonly. Core strips stored message metadata from messages delivered to the provider. System/messages mutations apply to the request draft, while prompt mutations persist. `generate`, `title` and `compaction` have independent hooks. | Shaped request goes through OpenAI transport. Sign in with ChatGPT token sharing updates session and cache-affinity headers and uses the direct OpenAI HTTP route. The legacy Codex credential methods set the Codex backend and default to WebSocket. | Use new user content as candidate portable seam. Plain external system append misses primary/branch under built-in order. Claude may reuse a live subprocess or fork from a checkpoint. Title uses a different utility prompt path. |
| Choose model by task and record assignment | Session create and switch-model API precede model resolution. Child tool precedence is explicit model, agent model, parent model. Experimental `model.resolve` can rewrite model and variant within the selected provider. `model.request` can change endpoint and headers, with the provider bridge limitations below. | Record session selection and effective request model separately. Child cache affinity can be shared with parent so cache IDs are unsuitable as lineage IDs. | Effective choice is translated to the bridge model and effort. Claude process controls are applied before input or parked tool results. An OpenCode endpoint hook is not a Claude transport routing seam. |
| Before, after, failed and stopped tools | Legacy event equivalents are a combination. `tool.hook("execute.before")` receives session, agent, message and call IDs, tool and input. Its typed failure can reject before execution. `execute.after` receives status, output/content/metadata or typed tool error and can change the result. Use durable `session.tool.called/success/failed` to reconcile actual terminal state, including cases where execution never reached after. Distinguish provider-executed tools using `executed`. `session.tool.progress` is ephemeral. Permission decisions have their own asked/replied events. | Locally executed OpenCode tools traverse the dispatcher. Provider-executed tools need event evidence and a visible host executable tool must be distinguished from a model-side feature. | Offered tools execute as OpenCode tools bridged to the subprocess by MCP. Stream conversion takes outer assistant messages and only maps offered tool names. Hidden Claude-side events and unoffered calls cannot be captured by the adapter. |
| First child turn and child outcome | OpenCode's native subagent dispatch authorizes first, creates or checks child lineage, calls `sessions.prompt`, and starts its background job. Child prompt is admitted before its job takes over start for an idle child. Inspect the child session on its own prompt/context hooks. Use durable execution outcomes and correlate the parent report with the child, rather than counting it as new independent work. | Native child can pick ChatGPT or another provider. Its own OpenCode IDs are available. | Native child can pick Claude Agent and still crosses the OpenCode admission hooks. A provider route does not enable independently configured Claude Code subagents or their hooks. |
| Compaction and continuity | `session.hook("compaction")` receives read/write request draft and can supply a result including a native replacement window. Compaction activity has started/ended/failed events. Manual, auto, native and background precompute paths can differ in timing; run both precomputed/automatic and explicit manual probes, and count successful persisted windows separately from precompute attempts. | Current token sharing uses summary compaction and lacks native `/responses/compact`. Check the legacy Codex route independently where native compaction is available and replacement content can be opaque. Evaluate the first effective primary request after compaction as well as the summarizer. | Claude Code native auto compaction is disabled. OpenCode owns compaction and Claude Agent can use a temporary branch for summary work. Validate continuity on both sides of the stored checkpoint. |
| Stop, cancel, failure and shutdown | Durable `session.execution.started/succeeded/failed/interrupted` describe execution episodes. Interrupted includes user, shutdown, superseded and inactivity. `experimental.idle` can modify later behavior via synthetic input and skips interruptions, failures and control-only work. OpenCode archive/delete are separate from idle and terminal episodes. Use distinct observation types or explicit reason mapping. | Native cancellation originates from the OpenCode runner. | OpenCode bridge propagates abort and drains or stops subprocess as applicable. Provider subscribes to terminal events to idle its native session and removes its mapping on OpenCode delete. Native lifecycle does not identify OpenCode user stops by itself. |
| Capture and modify HTTP/WS | `model.request` offers headers and endpoint after shaping. Native route may expose HTTP request/response and experimental WS handshake/send/receive hooks. Transport payloads are a poor universal memory seam and carry raw provider data. | Current token sharing (`chatgpt-token-sharing`) uses HTTP against `https://api.openai.com/v1` by default. Legacy Codex browser/device methods use the Codex backend and default to WebSocket. Count model requests at the session boundary and record the credential method for transport-specific probes. | The subprocess makes the Anthropic API calls. Spec states HTTP hooks never run on this path and per-request baseURL/header changes are unsupported. Observe normalized OpenCode output instead of credential-bearing frames. |

## Extension choice and limits

- **Native server plugin first.** The location-scoped server part supplies mutating hooks, typed events, disposable registrations and access to the current OpenCode API. TUI/GUI parts can add affordances. They are the wrong place to host cross-client observation or injection. The v2 SDK `session.prompt` handler and TUI v2 data client converge on server admission. Inspect CLI/headless server mode in the validation run rather than assuming every mode sends through this endpoint. [V2 plugin overview](https://opencode.ai/docs/build/plugins/) · [Hook registry](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/core/src/plugin/hooks.ts#L63-L108) · [Server prompt handler](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/server/src/handlers/session.ts#L289-L325) · [TUI data path](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/client/src/solid/data.ts#L1934-L1950)
- **Use durable event reconciliation beside hooks.** Live observation alone cannot guarantee capture after reconnect or cover pre-admission intent and the final provider context. Session logs, SDK lists, and message paging are read/recovery surfaces. Exercise replay boundaries, repository scoping, unfinished tool and execution records, and reconnect startup order in a controlled run. Budget and deduplicate on canonical IDs such as session, message, call ID and event sequence, preserving provider namespaced IDs as supporting provenance. [Session API](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/protocol/src/groups/session.ts) · [Messages API](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/protocol/src/groups/message.ts)
- **V1 plugin configuration acceptance does not imply V1 implementation compatibility.** The v2 normalizer accepts both singular `plugin` and plural `plugins`, but v2 server load decodes a default definition with an ID and `setup` or `effect`. The public migration guide maps V1 `chat.message`, transform and compaction names to different V2 shapes. Treat any existing V1-shaped shim as requiring a native port or a demonstrated translation layer. MCP alone offers explicitly invoked retrieval and says nothing about passive observation. [Config normalizer](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/core/src/config/normalize.ts#L203-L208) · [V2 module loader](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/core/src/plugin/module.ts#L168-L185) · [V1 migration guide](https://opencode.ai/docs/build/plugins/migrate-v1/)
- **Version-sensitive parts.** Experimental idle, same-provider model resolution, WS hooks and durable session logging need an exact OpenCode/client/plugin pin and smoke tests. The observation adapter should use public API types and treat internal Claude provider instruction translation as a diagnostic, without depending on it for common behavior. [Promise hook types](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/plugin/src/promise/session.ts) · [Server plugin docs](https://opencode.ai/docs/build/plugins/server/)

## Candidate proof checks for W3 and synthesis

For a matched task on the ChatGPT route and on Claude Agent, record admission, effective repo/model, first primary request, OpenCode tool execution before/terminal, a failed or cancelled tool, child start/injection and terminal, compaction and first post-compaction request, reconnect replay, and a second repository acting as an isolation control. Start in direct Claude Code to identify the real baseline the owner actually uses. Give each run distinct harmless memory canaries and test a fresh parent, first child request, resumed turn, and repeated request after tool output. Assert what the model received with the least revealing instrumentation available on each path. Compare appended system context and a bounded addition to newly admitted user content as separate probes. Measure replay duplication, retrieval time, and lost events across a deliberately dropped collector connection. Establish which learning inputs the ingest actually uses before trying to replay every available token and tool delta.

**Directional determination:** use a native v2 server plugin plus replay reconciliation as the first candidate. The deciding constraint is effective provider-visible, repository-correct memory on the first parent and child request, including resumed and post-compaction calls. Prove that separately from hook execution, and separately for the Claude Agent subprocess. The existing adapter's coverage is relevant baseline evidence only.
