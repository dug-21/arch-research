# W3 — Unimatrix capture, learning and context delivery

**Position — assemble a native OpenCode v2 adapter around the existing Unimatrix service, conditional on a narrow runtime trial.** Keep the shipped adapter as a reference for transport and frame normalization. It does not load as a v2 plugin and does not implement automatic prompt, child, or compaction injection even when loaded on v1. Stock v2 provides promising request-time extension points. The hardest requirement is verifying that memory reaches the right model request and that Unimatrix credits the correct repository, session, child, workflow cycle, and model for the work.

**Evidence pins.** Unimatrix source at `e2194af8c32c1fca8767c4e61a0667be4fd7566c`, with version `0.11.3` in the npm package and plugin manifests. OpenCode source at tag `v2.4.1`. The Claude baseline is Unimatrix's installer-managed Claude Code hooks at the same Unimatrix commit. No owner-local Claude binary, live subscription, agent session, database, or model request was exercised here. Unimatrix's vnc-049 tests are upstream prior evidence, with a specifically acknowledged lack of end-to-end child correlation. [Unimatrix snapshot](https://github.com/dug-21/unimatrix/tree/e2194af8c32c1fca8767c4e61a0667be4fd7566c) · [OpenCode snapshot](https://github.com/anomalyco/opencode/tree/v2.4.1) · [Upstream acceptance coverage](https://github.com/dug-21/unimatrix/blob/e2194af8c32c1fca8767c4e61a0667be4fd7566c/product/features/vnc-049/testing/RISK-COVERAGE-REPORT.md#L66)

## Where capture and memory delivery diverge

1. **V2 requires a new entry point.** The installer provisions a `.opencode/plugins/unimatrix.js` re-export and a v1 `plugin` list entry. The exported value is an async function returning a `Hooks` object. The v2 loader requires a default definition with an `id` and `setup` or `effect`. V2 migrates config and legacy discovery paths, but rejects this implementation shape. Preserve the existing plugin for v1 and adapt reusable internals behind a native v2 entry. [Unimatrix plugin entry](https://github.com/dug-21/unimatrix/blob/e2194af8c32c1fca8767c4e61a0667be4fd7566c/packages/unimatrix/opencode-plugin/unimatrix.js#L20-L46) · [Unimatrix installer](https://github.com/dug-21/unimatrix/blob/e2194af8c32c1fca8767c4e61a0667be4fd7566c/packages/unimatrix/lib/opencode-install.js#L209-L326) · [OpenCode loader](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/core/src/plugin/module.ts#L79-L129) · [Migration guide](https://opencode.ai/docs/build/plugins/migrate-v1/)
2. **Persisted attribution is uneven.** Generic `RecordEvent` stamps `source_domain=opencode` and a validated model ID. Longer prompts use `ContextSearch`, whose observation row sets both to NULL. Subsequent legacy domain derivation can label the shared event as Claude Code. Session registration and close requests also carry no such model stamp. The shim's cached requested model is a hint, especially at spawn or if the actual model differs. Exact request model identity needs a separate observation envelope or changes to Unimatrix's typed query attribution. Detectors are another boundary: the built-in OpenCode domain pack has no equivalent rules and Claude-specific rework exits on non-Claude provider. [Query observation fields](https://github.com/dug-21/unimatrix/blob/e2194af8c32c1fca8767c4e61a0667be4fd7566c/crates/unimatrix-server/src/uds/listener.rs#L1451-L1500) · [Provider-first ingest](https://github.com/dug-21/unimatrix/blob/e2194af8c32c1fca8767c4e61a0667be4fd7566c/crates/unimatrix-server/src/uds/listener.rs#L3228-L3264) · [Domain derivation](https://github.com/dug-21/unimatrix/blob/e2194af8c32c1fca8767c4e61a0667be4fd7566c/crates/unimatrix-server/src/services/observation.rs#L566-L600) · [OpenCode domain pack](https://github.com/dug-21/unimatrix/blob/e2194af8c32c1fca8767c4e61a0667be4fd7566c/crates/unimatrix-observe/src/domain/mod.rs#L85-L112)
3. **Separately observe query, result and delivery.** UDS retrieval uses strict search with similarity/confidence floors and session history, then records injection entries and deduplicates co-access. This happens before results return to the caller. It establishes service selection, not delivery, and co-access dedup is not protection against repeatedly placing the same memory into a prompt. A v2 adapter should key retrieval and application by parent or child session, trigger message, and selected entry IDs, and distinguish selected from applied. Let subsequent model steps reuse the selected context without producing fresh selection credit for every step. Record an explicit delivery acknowledgment if calibration requires it. [Selection and logging](https://github.com/dug-21/unimatrix/blob/e2194af8c32c1fca8767c4e61a0667be4fd7566c/crates/unimatrix-server/src/uds/listener.rs#L1644-L1815)
4. **Repository isolation follows the endpoint, not the model.** Local hook hashes a canonical path. The resolver follows a worktree's `.git` file when given the worktree directory, but the explicit directory path does not walk up from a subdirectory. Two independent clones hash separately unless deliberately attached to a common remote store. MCP config and telemetry transport must agree; otherwise a lookup can work against one store while observations accumulate in another or go missing. Keep raw telemetry per project. Any collective publication or lookup should have a deliberate, separately scoped interface. [Root and hash resolver](https://github.com/dug-21/unimatrix/blob/e2194af8c32c1fca8767c4e61a0667be4fd7566c/crates/unimatrix-engine/src/project.rs#L44-L136) · [Socket selection](https://github.com/dug-21/unimatrix/blob/e2194af8c32c1fca8767c4e61a0667be4fd7566c/crates/unimatrix-server/src/uds/hook.rs#L222-L235) · [Separate OpenCode MCP wiring](https://github.com/dug-21/unimatrix/blob/e2194af8c32c1fca8767c4e61a0667be4fd7566c/packages/unimatrix/lib/opencode-install.js#L473-L545)

## Provider-specific request delivery

**ChatGPT path.** V2 model request assembly applies `session.context` to primary requests and `session.compaction` to compaction requests, each with agent, model, session, and mutable system/messages/options. This is a stronger placement seam than a visible prompt append. Start with one request-local result and verify the effective content after provider transformation. Use the v2 event stream for observation, with reconnect reconciliation or own receipts where loss would invalidate attribution. An external subscriber alone cannot guarantee delivery before the first token. [OpenCode request assembly](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/core/src/session/model-request.ts#L265-L336) · [Per-path hooks](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/core/src/session/model-request.ts#L461-L470) · [Volatile stream contract](https://opencode.ai/docs/api/#event)

**Claude Agent path.** At v2.4.1 the provider runs the Claude executable with `settingSources: []`, `disableAllHooks: true`, no default tools, strict MCP and an OpenCode-owned MCP bridge. It installs its own SDK tool handlers. This supports the hypothesis that OpenCode provides the primary capture surface and that the usual Claude Code Unimatrix hooks do not double-record while using this provider. Verify it at runtime with a sentinel hook that emits a harmless marker and trace OpenCode tool completions; a parallel standalone Claude session remains a different producer. For injection, the bridge skips generic system-role messages in its message conversion, and a separate provider hook snapshots system instructions into options after omitting the first system part. Which plugin edits survive therefore depends on placement, transform order and whether the provider reuses an existing Claude session. A marker supplied through actual intended instruction or message channels, tested on new, resumed and first child requests, is the decision evidence. [Claude SDK invocation options](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/core/src/plugin/provider/claude-agent/claude/query-options.ts#L85-L142) · [Instruction conversion](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/core/src/plugin/provider/claude-agent/instructions.ts#L20-L53) · [Message conversion](https://github.com/anomalyco/opencode/blob/v2.4.1/packages/core/src/plugin/provider/claude-agent/language-model/convert-to-claude-message.ts#L9-L36)

## Staged validation

Use one real repository task with a pre-existing relevant memory and one decoy repository. On Claude Code, collect a baseline containing a parent turn, delegated task, successful and failed tools, cycle phase change, compaction, resumed work, and terminal outcomes. Run the same envelope separately on pinned OpenCode v2 ChatGPT and Claude Agent, with the relevant memory available through one repository-local Unimatrix endpoint. Verify model-effective prompt presence and event/readback correspondence, including child-to-parent cycle attribution, replay without duplicate credit, and absence of decoy context. During simulated observation or retrieval loss, distinguish durable replay, explicit loss and fail-open continuation. Reuse the existing MCP connection for agent-requested search or briefing early, but count automatic injection only when an intended model request contains the marker. If OpenCode's public hooks can place context reliably and the only gaps are Unimatrix wire/schema fields, extend Unimatrix first. If a provider cannot carry the memory into normal requests, report it as a provider-specific adoption blocker or keep it outside the standard workflow.
