# Workflow-harness ecosystem survey

**26 November 2026 UTC · workflow-harness-012 · directional source research**

Cross-repository memory is already feasible as storage, scoped retrieval, and controlled distribution. The open question is whether those pieces can enforce who may propose, approve, read, and retract shared knowledge while preserving auditable lineage. Stock OpenCode v2.4.2 supplies subagent session lineage and managed policy. The inspected path authenticates remote MCP at the connection and supplies the child session ID separately as metadata. That leaves independently verifiable child rights unresolved for the author's shell-access threat model. Workload attestation and isolated runtime precedents keep a separately governed composition plausible. The opencode-001 pilot remains staged. ## Evidence gaps in decision order

1. **Trusted child identity is the gate.** The stock OpenCode source settles the metadata-versus-authority distinction for this release, and leaves feasibility open for a separately governed composition. Evidence must connect one independently observed child to one authenticated memory principal with enforceable project and operation bounds and independent audit attribution. No runtime evidence or empirical go/no-go followed from the source recheck. [Targeted recheck](scout-identity-recheck.md)
2. **Promotion semantics and repository bootstrap.** Need evidence for opt-in inheritance of definitions and/or selected knowledge, trusted proposal and approval, source reference integrity, correction/quarantine, and retraction to consumers. Scope labels and graph filters address only part of this contract. [TUF v1.0.37, 2026-10-08](https://github.com/theupdateframework/specification/releases/tag/v1.0.37) · [Graphiti v0.32.1, 2026-11-24](https://github.com/getzep/graphiti/releases/tag/v0.32.1)
3. **Audit completeness and an independent anchor.** Need coverage of every material mutation, stable event identity, reconciliation across retries and restoration, and custody of the retained checkpoint outside the writing service. Witnessed receipts can verify recorded events. Completeness needs evidence about expected writes. Rekor's public witnessed deployment was unverified in this scan. [RFC 9162, 2021-12](https://www.rfc-editor.org/rfc/rfc9162.html) · [Rekor v2.3.0, 2026-06-10](https://github.com/sigstore/rekor-tiles/releases/tag/v2.3.0) · [Adjacent audit analysis](scout-adjacent.md#a3-audit-receipt-append-only-integrity-and-write-completeness-are-different-evidence)
4. **Workflow memory value and agent evolution.** Sessions can yield evidence and candidate experiences. A credible quality signal needs known-transfer work, independent held-out work, baseline or comparison cohorts, and stable agent/protocol/model/memory version identity. It should keep task quality, authorization, and inference cost separate. Retention, latency/freshness, and PII handling determine whether an expiring tier fits. [AgentCL v3, 2026-09-26](https://arxiv.org/abs/2606.02461v3) · [Agent Memory v2, 2026-09-22](https://arxiv.org/html/2606.06448v2)
5. **Recovery, privacy and portability.** Need a logical v1 migration contract for scoped entries, graph relations, correction/audit history and embedding version changes, plus physical recovery with a measurable restore point. Deletion from derived memory, cached contexts, exports and backups needs explicit semantics. Concurrent-client behavior, keys/encryption, quotas, and upgrade continuity remain unverified operational questions. [Pinned v1 export](https://github.com/dug-21/unimatrix/blob/2c7ea4ab0b384701aa4011a2704bb77228c1b233/crates/unimatrix-server/src/export.rs) · [PostgreSQL 19.0, 2026-11-19](https://www.postgresql.org/docs/release/19.0/)
6. **Actual Claude workflow equivalence and router results.** The source pins support model assignment and expose bridge constraints. The staged pilot still carries account entitlement/billing, model-visible capture and compaction, responsive human steering and cross-repo separation. Model policy economics and effectiveness depend on actual workload, provider and retry/cache evidence. [Prior run](../opencode-001/REPORT.md) · [Routing research](scout-literature.md)
